# 0006. Слой unit-тестов рядом с кодом, src/db на настоящей MySQL

## Правило для агента
Клади unit-тест рядом с модулем: `src/db/user.py` → `src/db/test_user.py`. Не используй моки и SQLite: тесты с БД работают с настоящей MySQL через fixture `session`, которая откатывает изменения. Запускай `src` и `tests` разными командами. Проверяй ошибки в обоих слоях и сверяй их текст целиком. Перед завершением задачи прогоняй полный `make test`.

## Контекст
Задача `issues/done/0002-unit-tests.md`. Были только e2e-тесты: они медленные и не могут проверить то, что не видно по HTTP, например истечение токенов.

## Решение
- Unit-тесты лежат рядом с модулями в `src/` и не поднимают сервер.
- Тесты `src/db/` и `src/backend.py` идут на настоящую MySQL без HTTP. Fixture `session` из `src/conftest.py` открывает обычную сессию. Эти функции только делают `flush`, поэтому выход из контекста без `commit` откатывает всё, что сделал тест.
- Тесты обоих слоёв проверяют ошибки вместе с их текстом: `assert_error` в e2e и `assert_error_status` в unit требуют ожидаемый `detail`. Этот текст видит человек, а непустой, но бесполезный `detail` иначе прошёл бы проверку.
- `make test-unit` запускает только unit-тесты, `make test` запускает оба слоя и копирует логи в `test_logs/` даже при падении.

## Почему
Настоящая база проверяет то, от чего зависит поведение: сравнение строк без учёта регистра и первичные ключи. Откат транзакции делает такие тесты быстрыми: весь слой проходит за секунды, а e2e занимает минуты.

## Варианты

### Настоящая MySQL без HTTP (выбран)
- Плюсы: тесты проверяют ту же базу, что и продакшн.
- Минусы: `make test-unit` поднимает контейнер с БД и ждёт 30 секунд.

### SQLite
- Минусы: `create_all` падает на `MEDIUMTEXT`, а для запуска пришлось бы менять схему. Правило сравнения строк `utf8mb4_0900_ai_ci` там отсутствует.
- Почему не выбран: тесты проверяли бы другую базу.

### Моки сессии
- Минусы: тесты проверяли бы только записанные в них ожидания.
- Почему не выбран: они не находят ошибок в запросах.

### Отдельная папка tests/unit/
- Плюсы: тестовые файлы не попадают в образ сервера.
- Минусы: тест лежит далеко от кода, а `autouse`-fixture `server` из `tests/conftest.py` пришлось бы переносить.
- Почему не выбран: пользователь попросил хранить тесты рядом с модулями.

## Последствия
- Unit-тесты попадают в образ `code_server` вместе с `src/`, в том числе в продакшн. На работу сервера они не влияют, зато образ сам содержит всё для их запуска.
- `AUTO_INCREMENT` при откате не возвращается, поэтому тесты не должны полагаться на конкретные id.

## Условия пересмотра
Если образ разделится на тестовый и продакшн, или если полный прогон unit-тестов станет занимать больше минуты.
