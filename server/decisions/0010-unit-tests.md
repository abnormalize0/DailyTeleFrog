# 0010. Unit-тесты в папках tests рядом с кодом

Заменяет [0006](0006-unit-tests.md): меняется только расположение тестов, остальные правила перенесены сюда без изменений.

## Правило для агента
Клади unit-тест в папку `tests/` на одном уровне с модулем: `src/db/user.py` → `src/db/tests/test_user.py`. Общие хелперы лежат в `src/tests/helpers.py`, fixtures в `src/conftest.py`. Не используй моки и SQLite: тесты с БД работают с настоящей MySQL через fixture `session`, которая откатывает изменения. Запускай `src` и `tests` разными командами. Проверяй ошибки в обоих слоях и сверяй их текст целиком. Перед завершением задачи прогоняй полный `make test`.

## Контекст
Пользователь попросил убрать тесты из папок с кодом: файлы модулей и тестов лежали вперемешку.

## Решение
- У каждой папки с тестируемым кодом есть подпапка `tests/`: `src/tests/`, `src/api/tests/`, `src/db/tests/`.
- `src/conftest.py` остаётся в `src/`: pytest применяет fixtures только к папке с этим файлом и её подпапкам, а тесты лежат в трёх разных ветках.
- E2e-тесты остаются в `tests/routes/`: они проверяют сервер целиком, а не один модуль.
- Тесты `src/db/` и `src/backend.py` идут на настоящую MySQL без HTTP. Fixture `session` открывает обычную сессию. Эти функции только делают `flush`, поэтому выход из контекста без `commit` откатывает всё, что сделал тест.
- Тесты обоих слоёв проверяют ошибки вместе с их текстом: `assert_error` в e2e и `assert_error_status` в unit требуют ожидаемый `detail`.
- `make test-unit` запускает только unit-тесты, `make test` запускает оба слоя и копирует логи в `test_logs/` даже при падении.

## Почему
Рядом с модулем тест легко найти, а в отдельной подпапке он не мешает читать код. Настоящая база проверяет то, от чего зависит поведение: сравнение строк без учёта регистра и первичные ключи.

## Варианты

### Подпапка tests рядом с модулем (выбран)
- Плюсы: код и тесты не смешаны, тест остаётся рядом с модулем.
- Минусы: в `src/` появляются три папки `tests`, а статическая проверка транзакций должна их исключать.

### Файлы test_*.py рядом с модулем (решение 0006)
- Почему не выбран: файлы модулей и тестов лежат вперемешку.

### Общая папка tests/unit/
- Почему не выбран: тест лежит далеко от кода. Отвергнут ещё в 0006.

Доводы против SQLite и моков записаны в 0006 и не изменились.

## Последствия
- Имена тестовых файлов по-прежнему не должны повторяться: в папках `tests` нет `__init__.py`.
- Unit-тесты попадают в образ `code_server` вместе с `src/`, в том числе в продакшн. На работу сервера они не влияют.
- `AUTO_INCREMENT` при откате не возвращается, поэтому тесты не должны полагаться на конкретные id.

## Условия пересмотра
Если образ разделится на тестовый и продакшн, или если полный прогон unit-тестов станет занимать больше минуты.
