# Задачи бэкенда

План работ над `server/`. Задачи лежат здесь, рядом с кодом, и попадают в репозиторий вместе с ним.

## Как вести

- Каждая задача лежит в своём файле `NNNN-короткое-имя.md`. Номера идут по порядку и не переиспользуются.
- Открытые задачи лежат в этой папке, поэтому `ls issues` показывает текущий план. Номер не задаёт приоритет.
- Закрытая задача переносится в `issues/done/`. Файл не удаляем: в нём остаётся контекст.
- Если задача приводит к архитектурному решению, оно оформляется записью в `decisions/`, а в задаче остаётся ссылка на неё.

## Формат файла

```markdown
---
id: 0006
title: Короткое название
areas: [api, db, tests]
date: 2026-11-01
---

# 0006. Короткое название

## Задача
Что нужно сделать и зачем.

## Что известно
Текущее состояние кода, ссылки на файлы и решения.

## Открытые вопросы
Что нужно решить до начала работы. Если вопросов нет, секция не нужна.

## Готово, когда
Проверяемые условия завершения.
```
