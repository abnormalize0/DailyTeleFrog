# 0026. Отдавать метаданные и реакции комментариев сразу в GET /articles/{id}

## Проблема
`GET /articles/{id}` отдаёт дерево комментариев только с `id`, `parent_id`, `is_deleted`, `author_username`, `text` и `answers` — без `creation_date`, `likes`, `dislikes`, `rating`, `is_liked` и `is_disliked`. Чтобы отобразить полноценную ветку комментариев, клиент вынужден делать отдельный `GET /comments/{id}` на каждый комментарий (N+1 по HTTP).

## Как возникает и к чему приводит
- *Как возникает:* `src/db/comment.py::from_article` не выбирает `creation_date` и не принимает `username` вызывающего (из `src/backend.py::get_article` он туда не передаётся), поэтому счётчики и флаги реакций комментариев вообще не собираются при загрузке статьи.
- *Негативный эффект:*
  - открытие статьи со 100 комментариями требует 101 HTTP-запрос (1 `GET /articles/{id}` + 100 `GET /comments/{id}`);
  - каждый `GET /comments/{id}` дополнительно открывает свою транзакцию, проверяет токен и делает несколько SQL-запросов — суммарно сотни лишних обращений к БД и заметная задержка отрисовки комментариев на клиенте.

## Желаемое поведение
- В `GET /articles/{id}` каждый **неудалённый** узел дерева `comments` дополнительно содержит `creation_date`, `likes`, `dislikes`, `rating` (`likes - dislikes`), `is_liked` и `is_disliked` (для неавторизованного запроса `is_liked` и `is_disliked` равны `False`).
- Удалённый комментарий (`is_deleted == True`) по-прежнему отдаётся только заглушкой (`id`, `parent_id`, `is_deleted: True`, `answers`), без автора, текста, даты и реакций — в соответствии с `decisions/0005-soft-delete.md`.
- Сбор счётчиков (`likes`, `dislikes`) и флагов (`is_liked`, `is_disliked`) для всех комментариев статьи выполняется пакетными SQL-запросами (O(1) запросов на статью, без N+1 в БД).
- Эндпоинт `GET /comments/{id}` сохраняется без изменений (удобен для точечного обновления счётчиков одного комментария после лайка/дизлайка).

## Готово, когда
- `GET /articles/{id}` отдаёт `creation_date`, `likes`, `dislikes`, `rating`, `is_liked`, `is_disliked` у каждого неудалённого комментария и не отдаёт их у удалённого.
- Сборка дерева комментариев с реакциями выполняется за O(1) SQL-запросов независимо от числа комментариев статьи (подтверждено unit-тестом с подсчётом запросов).
- Обновлён докстринг `api_articles_item_get` и тесты (`src/db/tests/test_comment.py`, `tests/routes/test_articles_item.py`); описаны новые поля для клиента.
- Полный `make test` проходит.
