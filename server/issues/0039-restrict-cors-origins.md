# 0039. Ограничить CORS разрешёнными origin через переменную окружения

## Проблема
Политика CORS открыта для любого внешнего origin (`*`), что позволяет сторонним сайтам выполнять кросс-доменные запросы к API от имени браузера пользователя.

## Как возникает и к чему приводит
- *Как возникает:* в `src/api/shared.py` задано `cors = CORS(app)` без списка разрешённых источников.
- *Негативный эффект:*
  - любой сайт получает `Access-Control-Allow-Origin: *` и может обращаться к API сервера;
  - в e2e-тестах (`tests/helpers.py::assert_preflight_allows`) проверяется только разрешение `http://client.test`, но не отказ посторонним origin.

## Желаемое поведение
- Читать список разрешённых origin из переменной окружения `CORS_ORIGINS` (строка через запятую с обрезкой пробелов); если переменная не задана или пуста — передавать пустой список `[]` (fail-closed, чтобы случайно не открыть `*` в продакшне).
- В тестовом запуске (`tests/conftest.py`) задавать `CORS_ORIGINS=http://client.test` для работы `assert_preflight_allows`.
- Добавить e2e-проверку: разрешённый origin получает `Access-Control-Allow-Origin`, а неразрешённый (например, `http://evil.test`) — не получает.
- Последствия для клиента: в `.env` при локальной разработке и деплое нужно явно прописать origin фронтенда в `CORS_ORIGINS`.

## Готово, когда
- `CORS(app)` настраивается из `CORS_ORIGINS` со значением по умолчанию `[]`.
- E2e-тесты проверяют как разрешённый, так и запрещённый origin.
- Прогнан `black` и полный `make test` проходит.
