# 0011. Ограничить значения и длину параметра indexes в GET /articles

## Проблема
`GET /articles` не проверяет, что переданные номера страниц `indexes` неотрицательные (`>= 0`), и не ограничивает количество элементов в списке `indexes`. В результате отрицательные индексы возвращают статьи с конца ленты вместо ошибки `400`, а длинный список (в том числе с повторами одного номера) позволяет кратно умножать число SQL-запросов за один HTTP-вызов.

## Как возникает и к чему приводит
- *Как возникает:* в `src/api/api_info.py::articles_get` для `indexes` указаны только `type: "list"` и `item_type: "int"` — без минимального значения элементов и без ограничения на длину списка. В `src/backend.py::pages_get` для каждого `index` из `indexes` выполняется Python-срез `article_ids[start:end]` (`start = index * config.articles_per_page`, `end = start + config.articles_per_page`), и для каждого `article_id` в срезе вызывается `get_article_preview`.
- *Негативный эффект:*
  - при `?indexes=-1` получается срез `article_ids[-5:0]` → пустой список и `200 OK` вместо ошибки валидации;
  - при `?indexes=-2` получается срез `article_ids[-10:-5]` → сервер возвращает `200 OK` с реальными статьями с конца ленты, нарушая контракт нумерации страниц с 0 (`src/api/routes/articles.py`);
  - передача длинного списка (`?indexes=0&indexes=1&...` или сотни повторов `?indexes=0&indexes=0&...`) заставляет сервер в цикле многократно вычитывать превью статей из БД за один запрос (при повторах результат ещё и перезаписывается в `pages[index]`), что даёт простой вектор для перегрузки БД и сервера.

## Желаемое поведение
- Каждый элемент `indexes` обязан быть целым числом `>= 0`: при любом отрицательном значении `GET /articles` возвращает `400 /errors/validation` с указанием поля `indexes` до обращения к БД.
- Длина входного списка `indexes` в одном запросе ограничена максимумом **10 элементов** (проверяется при валидации до дедупликации): при передаче более 10 элементов `GET /articles` возвращает `400 /errors/validation`.
- Повторяющиеся значения в `indexes` в пределах лимита (например, `?indexes=0&indexes=0&indexes=1`) тихо дедуплицируются: каждая уникальная страница собирается из БД ровно один раз и возвращается в `pages` по своему ключу.
- Ограничения (`>= 0` и максимум 10 элементов) описаны в схеме `src/api/api_info.py::articles_get`, отдаются клиенту через `OPTIONS /articles` и отражены в докстринге `api_articles_get`.

## Готово, когда
- `GET /articles` с отрицательными `indexes` (`-1`, `-2`, `[0, -1]`) возвращает `400 /errors/validation`.
- `GET /articles` с более чем 10 элементами в `indexes` (включая повторы) возвращает `400 /errors/validation`, а с 10 элементами проходит успешно.
- Дубликаты в `indexes` (в пределах 10 элементов) тихо дедуплицируются и не вызывают повторных запросов в БД для одной и той же страницы.
- Ограничения `indexes` заданы в `api_info.articles_get` и видны в `OPTIONS /articles`.
- Добавлены регрессионные тесты (unit и e2e), полный `make test` проходит.
