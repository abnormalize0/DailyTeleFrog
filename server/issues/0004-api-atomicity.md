# 0004. Обеспечить и зафиксировать атомарность API-методов

## Задача
Убедиться, что каждый API-метод либо применяет все изменения, либо не применяет ни одного, и закрепить это как проверяемое правило.

## Что известно
- Правило уже записано: пункт 4 в `decisions/0004-rest-api.md` требует `rollback` при ошибке и `commit` при успехе внутри `with get_session() as session:`.
- Похоже, что код ему следует: `commit` и `rollback` вызываются только в `src/api/routes/`, а функции из `src/db/` работают с переданной сессией. Но это результат поиска по коду, а не проверка каждого метода.
- Правило описывает только паттерн. Оно не определяет, что считается атомарностью, и ничем не проверяется: нет теста, что после ошибки посреди запроса данные остаются без изменений.

## Решение
См. `decisions/0009-api-atomicity.md` (статус `proposed`, ждёт согласия пользователя).

## Ответы на открытые вопросы
- Автоматический контроль нужен: `src/api/tests/test_transactions.py` проверяет правило по исходникам, а `tests/routes/test_atomicity.py` проверяет данные.
- Параллельные запросы частичных записей не оставляют, но ограничения БД превращали их в 500. По просьбе пользователя это исправлено здесь же. Гонка `POST /auth/refresh` оставлена осознанно и передана в `issues/0006-account-security.md`.

## Готово, когда
- Просмотрены все методы в `src/api/routes/`, и каждый метод с записью в БД выполняется в одной транзакции.
- Определение атомарности записано в `decisions/` и в скиле `dailytelefrog-new-api-method`.
- На методы с несколькими записями есть тесты: при ошибке на поздней стадии данные не меняются.
