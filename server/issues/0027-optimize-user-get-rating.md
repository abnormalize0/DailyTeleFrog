# 0027. Перевести расчёт user.get_rating с выгрузки ID и IN(...) на SQL JOIN + COUNT

## Проблема
`src/db/user.py::get_rating` выгружает в Python списки `id` всех статей и всех комментариев пользователя, а затем отправляет их обратно в MySQL в 4 отдельных запроса с `IN (...)`. Это создаёт лишние обращения к БД, гоняет по сети потенциально огромные списки ID и считает части рейтинга на разных MVCC-снимках под `READ COMMITTED`.

## Как возникает и к чему приводит
- *Как возникает:* в `user.get_rating` выполняется 7 отдельных SQL-запросов: `is_user_not_exist`, выборка всех `Article.id` автора, `COUNT` по `ArticleLike` и `ArticleDislike` с `article_id IN (...)`, выборка всех `Comment.id` автора (с `JOIN Article`), `COUNT` по `CommentLike` и `CommentDislike` с `comment_id IN (...)`.
- *Негативный эффект:*
  - у активного автора с тысячами комментариев/статей на каждый запрос `GET /users/me?requested_data=rating` все ID пересылаются из MySQL в Python и обратно дважды (раздуваются SQL-запросы и расход памяти, в пределе возможен упор в `max_allowed_packet`);
  - даже для нового пользователя без статей и комментариев выполняются лишние пустые `IN ()`-запросы;
  - 4 подсчёта идут в разных запросах и под `READ COMMITTED` видят разные моменты времени.

## Желаемое поведение
- `user.get_rating` вычисляет рейтинг целиком на стороне MySQL через `JOIN` + `COUNT(*)` (в идеале — одним `SELECT` с четырьмя скалярными подзапросами: лайки/дизлайки неудалённых статей и лайки/дизлайки неудалённых комментариев неудалённых статей), без выгрузки списков `id` в Python и без `IN (...)`.
- Сохраняется семантика `decisions/0005-soft-delete.md` (удалённые статьи, удалённые комментарии и комментарии удалённых статей не учитываются) и `decisions/0002-db-write-pattern-and-indexes.md` (подсчёт на лету без кэша).

## Готово, когда
- `user.get_rating` считает рейтинг через `JOIN` + `COUNT(*)` в одном SQL-запросе (после проверки существования пользователя), не выгружая списки `Article.id` и `Comment.id` в Python.
- Сокращение числа SQL-запросов и отсутствие `IN (...)` подтверждены unit-тестом в `src/db/tests/test_user.py`, а мягкое удаление по-прежнему учитывается корректно.
- Полный `make test` проходит.
