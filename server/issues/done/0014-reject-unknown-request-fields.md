# 0014. Отклонять неизвестные поля в JSON-теле и query-строке запросов

## Проблема
Валидация параметров API проверяет только поля, описанные в схеме метода (`api_info`), и молча игнорирует любые лишние ключи в JSON-теле и query-строке. Из-за этого опечатки в именах полей и несовпадения стиля именования (например, `sub_tags` вместо `sub-tags`) не вызывают ошибку и тихо теряются.

## Как возникает и к чему приводит
- *Как возникает:* `src/api/shared.py::check_structure` и `read_query` перебирают только элементы из `pattern` (`api_info.*`) и не проверяют наличие ключей, которых нет в схеме. В `src/backend.py::update_user_info` лишние ключи также молча пропускаются.
- *Негативный эффект:*
  - запрос с опечаткой в необязательном поле (например, `PATCH /users/me` с `{"nikname": "Vasya"}` или `{"sub_tags": ["games"]}`, `POST /articles` с `{"tag": ["a"]}`, `GET /articles?indexes=0&sort_by=rating`) проходит валидацию и отвечает `200`/`201`/`204`;
  - клиент уверен, что изменение применилось или фильтр сработал, хотя сервер тихо проигнорировал параметр.

## Желаемое поведение
- Строгая проверка неизвестных полей работает на уровне `src/api/shared.py` и для JSON-тела (`read_body` / `check_structure`), и для query-строки (`read_query`).
- Если в запросе присутствует хотя бы один ключ, не описанный в схеме метода в `api_info`, сервер сразу возвращает `400 /errors/validation` (`Wrong request parameters structure`) с указанием каждого лишнего поля в `errors` (например, `{"name": "<field>", "reason": "unknown field"}`) — до проверки авторизации и без обращения к БД.

## Готово, когда
- Передача любого неизвестного поля в JSON-теле или query-строке во всех методах, использующих `read_body` и `read_query`, возвращает `400 /errors/validation` с этим полем в `errors`.
- Общая проверка `tests/helpers.py::check_endpoint_structure` и unit-тесты `src/api/tests/test_shared.py` проверяют отклонение неизвестных полей в теле и query-строке.
- Полный `make test` проходит.
