# 0021. Запретить одновременную передачу username и email в is_user_not_exist и check_password

## Проблема
В `src/db/user.py::is_user_not_exist` и `check_password` при одновременной передаче `username` и `email` ветка `if email:` молча перезаписывает результат поиска по `username`, а при передаче обоих пустых значений функции молча считают пользователя несуществующим.

## Как возникает и к чему приводит
- *Как возникает:* обе функции принимают необязательные `username` и `email` и выполняют два последовательных независимых `if` (`if username: ...` затем `if email: ...`) вместо проверки, что передан ровно один идентификатор.
- *Негативный эффект:* при прямом вызове из Python (например, из нового кода или тестов) `check_password(session, pass_b, username="user_a", email="b@test.test")` делает лишний SQL-запрос по `user_a`, затем перезаписывает результат запросом по `email` пользователя B и возвращает `True`, маскируя ошибку вызывающего кода.

## Желаемое поведение
- `user.is_user_not_exist` и `user.check_password` требуют передачи ровно одного непустого идентификатора (`username` XOR `email`): при передаче обоих одновременно или отсутствии обоих сразу выбрасывается `ValueError` (это нарушение программного контракта внутренней функции `src/db/`, аналогично проверке в `POST /auth/login` на уровне API).
- Выполняется ровно один поиск — либо по `username`, либо по `email`.

## Готово, когда
- Вызов `user.is_user_not_exist` и `user.check_password` одновременно с `username` и `email` или без обоих поднимает `ValueError`.
- Поведение для корректных вызовов (только `username` или только `email`, включая пустую строку во втором аргументе из `backend.login`) не изменилось.
- Добавлены unit-тесты в `src/db/tests/test_user.py`, полный `make test` проходит.
