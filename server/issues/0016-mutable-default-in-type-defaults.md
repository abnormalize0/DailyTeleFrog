# 0016. Убрать разделяемый изменяемый список в api_info.type_defaults

## Проблема
`api_info.type_defaults` хранит один общий экземпляр изменяемого списка `[]`, а `shared.fill_default` подставляет ссылку на него напрямую без создания нового объекта. Из-за этого все необязательные списковые параметры во всех запросах указывают на один и тот же объект `list` в памяти.

## Как возникает и к чему приводит
- *Как возникает:* в `src/api/api_info.py` объявлен словарь `type_defaults = {"int": None, "str": "", "list": [], "bool": True}`. В `src/api/shared.py::fill_default` при отсутствии поля выполняется прямое присваивание `data[value["name"]] = api_info.type_defaults[value["type"]]`. Сейчас через `fill_default` проходят `POST /articles` (поле `tags`) и `GET /articles` (поля `include_tags`, `exclude_tags`, `include_authors`, `exclude_authors`).
- *Негативный эффект:*
  - внутри одного запроса `GET /articles` все четыре отсутствующих фильтра (`include_tags`, `exclude_tags`, `include_authors`, `exclude_authors`) ссылаются на один и тот же объект списка;
  - любая in-place мутация такого списка (`append`, `extend`, `sort`, `clear`) в одном обработчике молча изменит значение по умолчанию сразу для всех остальных списковых параметров и для всех последующих HTTP-запросов до перезапуска сервера — это классическая «мина замедленного действия», приводящая к трудновоспроизводимым багам между запросами разных пользователей.

## Желаемое поведение
- Каждый вызов `shared.fill_default` подставляет для каждого отсутствующего поля изменяемого типа (`list`, а также на будущее `dict`) новый независимый экземпляр (например, через фабрики в `type_defaults` или копирование в `fill_default`).
- Мутация списка, подставленного `fill_default` для одного поля одного запроса, не влияет ни на другие поля того же запроса, ни на последующие вызовы `fill_default`.

## Готово, когда
- Два вызова `shared.fill_default` (и два списковых поля в одном вызове) получают разные экземпляры `list` (`is not`).
- Изменение возвращённого по умолчанию списка не отражается на следующем вызове `shared.fill_default`.
- Добавлен регрессионный unit-тест в `src/api/tests/test_shared.py`, полный `make test` проходит.
