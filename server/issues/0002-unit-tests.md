# 0002. Сделать unit-тесты

## Задача
Добавить слой unit-тестов в дополнение к существующим e2e-тестам.

## Что известно
- Сейчас есть только e2e-тесты в `tests/routes/`: перед каждым тестом таблицы пересоздаются, поднимается настоящий `start.py -t`, а общение идёт по HTTP. Это долго и не позволяет проверять отдельные функции напрямую.
- `CLAUDE.md` прямо говорит, что отдельного слоя юнит-тестов и моков нет. После этой задачи раздел «Запуск тестов» нужно обновить.
- Fixture `server` из `tests/conftest.py` рассчитана на e2e. Unit-тесты не должны поднимать сервер.

## Открытые вопросы
- Что считаем unit-тестом для `src/db/`: вызов функции на настоящей MySQL без HTTP или на изолированной базе?
- С каких модулей начинаем? Проще всего начать с кода без обращения к БД: хеширования паролей в `src/db/user.py` и `src/request_status.py`.

## Готово, когда
- Unit-тесты лежат отдельно от `tests/routes/` и запускаются отдельной командой, без сервера.
- `make test` запускает и unit-, и e2e-тесты.
- `CLAUDE.md` описывает оба слоя.
